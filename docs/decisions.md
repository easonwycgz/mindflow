# Engineering decisions
- React/TypeScript/Vite PWA, Dexie/IndexedDB, Tailwind 4. No backend. Public demo is the only bundled card; deployment includes only dist/.
- Authoritative schema and example remain unchanged at the root and are copied byte-for-byte into contracts/. Ajv Draft 2020-12 plus URI formats performs protocol validation; Zod is the boundary and backup envelope validator, avoiding a second divergent handwritten protocol.
- Import: maximum 2 MiB UTF-8, tree depth 16, JSON container depth 64 and 50,000 total values. SHA-256 uses recursively sorted keys; array order remains meaningful. Same hash is rejected. Changed content creates a separate card/version with its own application ID, preserving the old card and reading state. There is no implicit title-based overwrite.
- Content records hold generated UUID, timestamps and hash. Reading and settings use separate stores. No content leaves IndexedDB except an explicit user-initiated backup download.
- Backup v1 contains all three stores and a SHA-256 integrity checksum (not encryption or authentication). Restore validates schema, content hashes, uniqueness and references before one all-or-nothing transaction. Maximum backup 40 MiB, 500 cards and the global value bound. Failure preserves current stores; UI warns before replacing all data.
- Render user content as React text, including Markdown markers. No HTML interpreter, links or remote image rendering. This intentionally chooses plain text allowed by the content protocol over rich Markdown.
- Service worker precaches only build assets, never private cards. No background sync. Updates wait for explicit user action. CSP on Cloudflare blocks external connections and images; trusted static Ajv schema compilation requires unsafe-eval, but inline script remains forbidden.
- Reading section, selected node, favorite and scroll offset persist. Scroll saves after 150 ms idle; abrupt termination may lose the last scroll movement. Browser/system eviction is outside application control; backups are required.
- iPhone styles use safe-area insets, 44px controls, Chinese wrapping and reduced-motion override. Chromium mobile emulation is not iOS validation.

## Round 2 superseding decisions
- QA-001: single-card value/depth bounds remain unchanged. Backup envelope traversal has a sum-of-cards budget (500 × (50,000 + bounded metadata)); every card is independently revalidated. One capacity guard (500 cards, 40 MiB with conservative reading/settings headroom) runs at import, export and restore. Export validates the same references/hashes before emitting a compact v1 envelope; old pretty-printed v1 backups remain accepted. Legacy over-capacity stores are refused clearly rather than emitting a false-success backup; a recovery/volume UI is not implemented in this candidate.
- QA-002: both paste and file entries call the same importCard boundary. No clipboard permission or network API. Multiple cards are imported consecutively without modifying the card protocol.
- QA-003/005: tree children use native disclosure; selected ancestors reopen on restore. Node body precedes navigation, selection scrolls/focuses it, and a return action retains access to the tree. Mobile existing libraries render reading first instead of a management-first page.
- QA-006: horizontal touch gesture is bounded to reading, with 80px minimum, 2:1 direction ratio and 1.2s window. Interactive controls, tree navigation, selected text and multi-touch are excluded. Native vertical scroll remains enabled. Explicit previous/next buttons provide keyboard alternatives.
- QA-007/008: export UI discloses plaintext contents; a small React-only Markdown subset adds headings, lists and bold. Suspicious HTML-containing input remains visibly inert source; no HTML parser or external image/link renderer. Full mathematics/complex Markdown are V1.1 work, not claimed supported.
- QA-009 supersedes earlier unsafe-eval rationale: Ajv standalone generation + build-time esbuild bundles required helpers. Generated validator is committed, regenerated from unchanged contracts on prepare/build/test/typecheck. No runtime code compilation; actual header-enforcing test server exercises the strict CSP.
