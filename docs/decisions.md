# Engineering decisions
- React/TypeScript/Vite PWA, Dexie/IndexedDB, Tailwind 4. No backend. Public demo is the only bundled card; deployment includes only dist/.
- Authoritative schema and example remain unchanged at the root and are copied byte-for-byte into contracts/. Ajv Draft 2020-12 plus URI formats performs protocol validation; Zod is the boundary and backup envelope validator, avoiding a second divergent handwritten protocol.
- Import: maximum 2 MiB UTF-8, tree depth 16, JSON container depth 64 and 50,000 total values. SHA-256 uses recursively sorted keys; array order remains meaningful. Same hash is rejected. Changed content creates a separate card/version with its own application ID, preserving the old card and reading state. There is no implicit title-based overwrite.
- Content records hold generated UUID, timestamps and hash. Reading and settings use separate stores. No content leaves IndexedDB except an explicit user-initiated backup download.
- Backup v1 contains all three stores and a SHA-256 integrity checksum (not encryption or authentication). Restore validates schema, content hashes, uniqueness and references before one all-or-nothing transaction. Maximum backup 40 MiB, 500 cards and the global value bound. Failure preserves current stores; UI warns before replacing all data.
- Render user content as React text, including Markdown markers. No HTML interpreter, links or remote image rendering. This intentionally chooses plain text allowed by the content protocol over rich Markdown.
- Service worker precaches only build assets, never private cards. No background sync. Updates wait for explicit user action. CSP on Cloudflare blocks external connections and images; trusted static Ajv schema compilation requires unsafe-eval, but inline script remains forbidden.
- Reading section, selected node, favorite and scroll offset persist. Scroll saves after 150 ms idle; abrupt termination may lose the last scroll movement. Browser/system eviction is outside application control; backups are required.
- iPhone styles use safe-area insets, 44px controls, Chinese wrapping and reduced-motion override. Chromium mobile emulation is not iOS validation.

## Round 2 superseding decisions
- QA-001: single-card value/depth bounds remain unchanged. Backup envelope traversal has a sum-of-cards budget (500 × (50,000 + bounded metadata)); every card is independently revalidated. One capacity guard (500 cards, 40 MiB with conservative reading/settings headroom) runs at import, export and restore. Export validates the same references/hashes before emitting a compact v1 envelope; old pretty-printed v1 backups remain accepted. Legacy over-capacity stores are refused clearly rather than emitting a false-success backup; a recovery/volume UI is not implemented in this candidate.
- QA-002: both paste and file entries call the same importCard boundary. No clipboard permission or network API. Multiple cards are imported consecutively without modifying the card protocol.
- QA-003/005: tree children use native disclosure; selected ancestors reopen on restore. Node body precedes navigation, selection scrolls/focuses it, and a return action retains access to the tree. Mobile existing libraries render reading first instead of a management-first page.
- QA-006: horizontal touch gesture is bounded to reading, with 80px minimum, 2:1 direction ratio and 1.2s window. Interactive controls, tree navigation, selected text and multi-touch are excluded. Native vertical scroll remains enabled. Explicit previous/next buttons provide keyboard alternatives.
- QA-007/008: export UI discloses plaintext contents; a small React-only Markdown subset adds headings, lists and bold. Suspicious HTML-containing input remains visibly inert source; no HTML parser or external image/link renderer. Full mathematics/complex Markdown are V1.1 work, not claimed supported.
- QA-009 supersedes earlier unsafe-eval rationale: Ajv standalone generation + build-time esbuild bundles required helpers. Generated validator is committed, regenerated from unchanged contracts on prepare/build/test/typecheck. No runtime code compilation; actual header-enforcing test server exercises the strict CSP.

## Round 3 superseding decisions
- Font mutations now use transactional patches and serialized/revision-checked intents, with explicit commit acknowledgement and failure UI. A tiny synchronous font-only localStorage journal handles refresh before commit; no card content is stored there. Other settings writes patch the latest row instead of replacing a captured React snapshot. See settings.ts and round3-compatibility.md.
- Returning from body focuses the selected tree button and restores ancestors, with first-button/container fallback and native Tab/Enter plus directional navigation. Existing automatic scroll restoration remains.
- Legacy501 libraries have a bounded multi-file transfer path using unchanged v1 envelopes plus a separate manifest; aggregate limit40MiB/max2000 cards/max16×8MiB parts, validated globally before one atomic three-store replacement. Standard single-backup limits stay unchanged. See volumes.ts and the compatibility design for actual dependency/resource analysis.
- QA-008 remains PARTIAL, consistent with the locked contract and B's scope finding. Explicit V1.1 backlog records full math, tables and fenced-code rendering.
- Public synthetic-only text evidence is an explicit user-authorized exception to the normal no-generated-artifacts rule. CI also emits readable step summaries; private browser data and credentials remain prohibited.

## Round 4 — superseding only large-migration resource architecture
- Current settings/focus/Markdown fixes and the primary v1 database remain unchanged. App adds a migration tool; dedicated migration.html avoids the normal reader's whole-library loading.
- New paged packaging uses unchanged v1 parts, a constant-size root and ordered hash chain. Counts/total bytes have no former2000/40MiB product cap; each card/part retains safety limits. Four-record source/target batches, disk indexes and sequential File.text avoid aggregate JavaScript arrays.
- Export uses one readonly snapshot, spools parts to a separate workspace or writes a user-selected local directory without workspace allocation. Completion root is last. Restore stages/validates every part first, then atomically replaces the original three stores; external staged reads keep the native transaction alive via Dexie.waitFor. No main DB version upgrade.
- Physical quota/native transaction resource limits remain; non-directory/no-space combinations are explicitly unresolved. Direct directory core was tested with real local file sink, not claimed as manual picker or Safari validation.
- Original historical raw logs remain inaccessible (APIForbidden, exact route404); source/lock identity and failing step recovered, unique timeline not recovered. User requests owner/B evaluation of new closure criteria; gate remainsOPEN until a formal decision.

## Round 5 — integrity proof at use and space-constrained export
- The fourth-round ready flag/content hash was insufficient for reading and stored metadata. Preserve exact original file texts in restore workspace files (index0 root, 1..N parts), in the same transaction as derived rows and receipts. No primary schema, official card schema, v1 envelope or paged packaging format changes.
- Promotion recomputes original file checksums/chain, compares complete canonical derived records, writes the same private parsed values, reads back each written batch in the destination transaction and acknowledges only after native complete. A concurrent staging change after copying cannot alter these private values; never resolve the write from mutable rows again. Do not mistake this for cross-database distributed atomicity or cryptographic authentication.
- An initial whole-workspace readonly lock with cross-transaction bound target tables passed fake-indexeddb but failed native Chromium with TransactionInactiveError. It was removed, not hidden by test changes. The final implementation uses short workspace transactions and private value snapshots, preserving the proven main-transaction lifecycle.
- Restore now needs original part proofs in addition to indexed rows; storage estimates must include both and the native transaction log. Quota failures roll back and never clear the unique source outside a replacement transaction.
- A new explicit per-part download sink does not write workspace records, preserving the same source snapshot and completion-root-last rule. User interaction is bounded by the existing60s external-IO deadline; cancelled/timed-out/blocked downloads retain source and identify incomplete files. Download request/user acknowledgement is not proof of bytes on disk; reselect all files for validation before replacement. Safari/iPhone and real disk exhaustion remain unverified.
