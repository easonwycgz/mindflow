# UX-01 手机阅读入口：待确认设计方案

本次仅提交设计与隔离原型；生产 `App.tsx`、`style.css`、阅读状态和 UX-03 均未修改。未批准、未发布，也不表示 B 验收通过。

## 现状与测量口径

B 发现首屏缺失核心收获。A 本次复测确认：390×844 下，当前标准字有部分核心完全在屏外，大字下八卡均完全在屏外。此前 A 的标题归一化、仅检查核心起点的测量不足以证明实际首屏能完整阅读；本次不沿用该结论。

使用同一八份只读脱敏原件，导入前逐一核对 SHA-256（C1—C8 与 `ux1-corpus-review.md` 一致）。Chromium 154.0.8037.57，Playwright 1.64.1，390×844，有触摸；标准/大字的正文、核心和 caveat 分别保持 16/20 CSS px。每个场景使用独立浏览器上下文，关闭导入结果提示。实际内容、截图、trace、浏览器资料没有提交或上传。

两种入口分别测量：普通保存位置为 0 的阅读入口；从另一张虚构卡通过真实“随机一张”进入目标卡。当前版本和方案 A 不额外滚动。B 原型在组合 DOM 后，重新应用同一个保存零位置或原有标题锚点，未滚到核心。非零旧位置不是首屏优化的测量对象。

“完整”要求核心原文文本块 `getBoundingClientRect()` 的 top≥0 且 bottom≤844；“部分”表示与视口相交但无法完整显示；“屏外”表示不相交。未以标题或核心容器起点替代原文。检测无横向溢出、字号未缩小、核心和首条 caveat 原文相同、外站请求 0。数值为 CSS px，以下区间向外取整。浏览器动态工具栏、安全区、不同字体尚未验证。

## 两个候选

**A：只压缩留白。** 保留现有 DOM 和控制顺序，缩小移动端页边距、卡片及标题留白和提示区段间距；正文不截断、不缩字号，命中区仍至少 44px。见 `ux1-mobile-layout-proposal.css`。该方案实测不足，不能单独解决问题。

**B：精简应用工具区（建议负责人审阅）。** 在 A 基础上将品牌和临时阅读的长说明集中到“阅读状态”展开区；在线/离线状态仍常显。临时模式摘要明确写“随看中 · 不自动保存”，“继续上次阅读”仍在外部直接可用；“从这里继续”的明确保存操作在展开区内一次操作可达。收藏、上一张/下一张及四个阅读标签仍直接可用。

B 不移动事实内容：标题 → 原文提醒 → Hook/标签 → 核心收获的相对顺序不变；全部 caveats、原始顺序及全文入口保留。不改变原文，不截断，不缩小正文；仅将应用自有的重复说明收紧为“原文提醒，未作当前核实。”，并压缩工具和段落留白。完整摘要、全部要点、知识树、FAQ、短阅读结束入口仍保留。没有按卡片名称、ID 或关键词制作特例。

B 的工具布局和“从这里继续”入口多一次展开属于待批准的体验权衡。本次提供 `ux1-mobile-controls-proposal.css` 和 `ux1-mobile-controls-prototype.mjs`，仅用于隔离浏览器的几何测量；DOM 适配器不是可交付 React 实现，不接入 src/public/dist/构建/CI，也未证明交互验收通过。

## 确认后才可实施的技术与验收安排

使用 React 条件布局实现移动工具区；保持现有按钮回调、临时模式、视图令牌和保存屏障，不新增持久字段。关闭工具区时，将其内部焦点恢复到展开按钮；切卡、随机、退出及重新渲染后不得停在隐藏内容。原型直接移动 DOM 的方式不得进入生产代码。

必须在 390×844 标准/大字、桌面、原 Pixel 7 配置重测：所有原文可达；核心和 caveat 字节/顺序不变；完整摘要/全部要点/知识树/FAQ 入口可用；长内容降级、16 层树和返回焦点；临时随机不写续读，明确采纳才保存；字号切换、快速随机、恢复和事务失败。保持严格 CSP、无外部请求及离线功能。新增独立测试，不修改原 B 断言或将其 FAIL 记为 PASS。

布局变化会改变文档高度，旧的非零像素 scroll 不能仅凭状态字段未变就声称恢复等价。建议非零既有续读入口保留旧布局，直到用户明确回到快速阅读；或另行批准语义锚点适配。两者均需负责人选择、配套 focus/scroll 测试后实施，不能本轮静默迁移。当前版本布局未改，原续读行为保持。

待确认：B 工具区权衡、应用说明文案、非零旧位置的布局策略和最终验收目标。UX-03 的关键 caveat 优先级仍单独待定。真实 iPhone Safari、VoiceOver、主屏离线冷启动、动态工具栏及额外字体均 **NOT VERIFIED**。本设计不决定历史 summary 默认可见合同如何治理。
